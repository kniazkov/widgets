# NumberField и QuantityField

`NumberField` — текстовый редактор точного числа. `QuantityField` — готовый
`FormField` с таким редактором, подписью, help/error и кнопками «−»/«+».
Оба показаны в AllWidgets, карточка «Числа без потери точности».

## Контракт значения

`NumberModel.decimals()` хранит `BigDecimal`, по умолчанию шаг `0.01`;
`NumberModel.integers()` принимает только целочисленную запись, шаг `1`.
В JSON передаётся **строка**, в браузере используется `input type=text`
с `inputmode=decimal`/`numeric`. В вычислениях нет `parseFloat`, JS Number,
округления или автоматического приведения к `long`.

```java
NumberField price = new NumberField();
price.setLocale(Locale.forLanguageTag("ru"));
price.setValue(new BigDecimal("9007199254740993.01"));
FormField row = new FormField("price", "Цена", price);
row.setRequired(true);
price.setConversionMessage("Введите число с запятой.");
row.setConstraintMessages("Укажите цену.", "Проверьте границы и шаг.");
form.addField(row);
```

`getValue()` возвращает `Optional<BigDecimal>` только для корректного непустого
значения. `clear()` оставляет поле пустым, не записывает ноль. Пустота допустима
для модели, обязательность задаётся через `FormField.setRequired(true)`.
`NumberValue.empty()/of(BigDecimal)` — неизменяемая оболочка для типизированного
`Model<NumberValue>`. Равенство использует стандартный `BigDecimal.equals`,
включая scale; числовые границы сравниваются через `compareTo`.

Текстовая модель сохраняет промежуточные `-`, `-,`, `12,` без исправления ввода.
Они пока некорректны; `getValue()` не возвращает старое число. При отправке формы
они дают отдельную ошибку преобразования `setConversionMessage`, а не ошибку
min/max/step. `getValueModel().status()` различает:

| Статус | Значение |
| --- | --- |
| `EMPTY` | Пустая строка; валидна для необязательного поля |
| `VALID` | Число удовлетворяет всем ограничениям |
| `CONVERSION` | Незавершённая/неверная запись, чужой разделитель, экспонента |
| `PRECISION` | Превышен лимит размера/точности |
| `BOUNDS` | Нарушены включительные границы |
| `STEP` | Число не лежит на сетке шага |

Публичный `setValue` принимает только корректное значение и бросает
`IllegalArgumentException` **до изменения модели** при нарушении контракта.
Для ввода с ошибками используется `setText` или `textModel().setData`.
`setTextModel` нельзя заменить произвольной моделью: связь с точным числом
является частью контракта. Несколько NumberField могут использовать один NumberModel.
Модель требует того же page context, что и другие SingleThreadModel.
`deriveWithData` создаёт независимую модель с копией ограничений и локали.

## Локаль, формат и ограничения ресурсов

По умолчанию `Locale.US`: `1234.50`. Для `ru` — `1234,50`. Сохраняются scale,
концевые нули и сырой ввод; разделителей групп разрядов нет. Поддерживаются
локали с десятичной точкой/запятой и ASCII-цифры. Не принимаются пробелы,
`+`, экспоненты, `NaN`, `Infinity`, группировка, Unicode-цифры. Например,
`1,234` в ru — дробное число (при подходящем шаге), не 1234.
В целочисленном режиме `1.0` также отклоняется: требуется запись `1`.

`setLocale` явно заменяет разделитель у корректного значения, не меняя числа
и scale. При неверном/незавершённом вводе бросает `IllegalStateException`:
сначала исправить/очистить поле. Локаль принадлежит общей модели.
Фокусированный редактор применяет серверный текст по обычным правилам InputField
(без замены текста и прыжка каретки посреди редактирования); при смене локали
из приложения следует сначала завершить редактирование.

Лимиты: максимум 256 значащих цифр, scale от 0 до 64; входная строка — до
512 UTF-16 единиц. Ограничения действуют и на конфигурацию. BigDecimal с
отрицательным scale, например `new BigDecimal("1E+3")`, нужно передавать в
обычной форме `new BigDecimal("1000")`. Длинный целочисленный ввод не
переполняет long; превышение документированного лимита даёт ошибку, не округление.

## Границы и точный шаг

```java
NumberModel model = NumberModel.decimals();
model.configure(NumberValue.of(new BigDecimal("0.05")),
    NumberValue.of(new BigDecimal("0.36")), new BigDecimal("0.10"));
NumberField field = new NumberField(model);
```

Обе границы включены. Сетка шага отсчитывается от min, если min задан, иначе
от нуля. В примере допустимы `0.05`, `0.15`, `0.25`, `0.35`; `0.36` находится
в границах, но не на сетке. Отсутствующую границу задают `NumberValue.empty()`.
Шаг строго положителен; неверная конфигурация отклоняется атомарно.
Изменение min/max/step сохраняет сырой текст и немедленно перепроверяет его.
Недопустимое старое значение **не зажимается автоматически** в новые границы.

## QuantityField

```java
QuantityField count = new QuantityField("count", "Количество");
count.setActionNames("Уменьшить количество", "Увеличить количество");
count.getEditor().getValueModel().configure(NumberValue.of(BigDecimal.ZERO),
    NumberValue.of(new BigDecimal("5")), BigDecimal.ONE);
count.getEditor().setValue(new BigDecimal("2"));
count.setRequired(true);
form.addField(count);
```

Конструктор с `NumberModel` позволяет дробное количество, например вес с шагом
`0.25`. `getEditor()` возвращает NumberField; обычные FormField API для help,
required, read-only, ошибок и имени продолжают работать. FormField теперь
допускает наследование; защищённый `addEditorAction` размещает кнопку рядом
с редактором, сохраняя связь label, editor, focus и проверки владения.

Кнопки используют один `NumberModel.move(-1/1)`; он повторно проверяет текущие
границы на сервере. Кнопка отключена, если следующий шаг недопустим. Для
неверного ввода обе отключены: сначала исправить значение вручную. Из пустоты
первое действие устанавливает min или ноль, только если такой кандидат допустим.
Если нет min, а весь диапазон отрицательный, пустое поле нужно заполнить вручную.

Каждое нажатие/активация делает **один** шаг. Удержание не запускает таймер
автоповтора. Кнопки доступны через Tab и Space/Enter; Enter в самом редакторе
отправляет Form. Во время IME composition Enter не отправляет форму. Количество
не имеет role=spinbutton и не перехватывает стрелки: это текстовое поле с двумя
именованными нативными кнопками, не имитация системного number input.

`count.getEditor().disable()` и `setReadOnly(true)` блокируют кнопки; замена
реактивной disabled-модели также учитывается. Уже поставленное в очередь действие
повторно проверяет состояние редактора. Снятие/перенос редактора отменяет право
композита менять его. Подписки снимаются при dispose. Числовой max — не
авторизация и не резервирование складских остатков: бизнес-права и наличие
приложение проверяет отдельно при исполнении операции.
