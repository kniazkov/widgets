# Сообщения и состояние операций

`Alert`, `FieldError`, `EmptyState`, `Busy`, `Progress` и `Toast` — блочные
виджеты. Они показывают обычный текст, не интерпретируют HTML, поддерживают
кириллицу и перенос длинных слов. Все подписи задаёт приложение: встроенных
английских сообщений и кнопок нет. Существующие виджеты сохраняют свой API.
Пример со всеми шестью классами находится в `AllWidgets`, в карточке
«Сообщения и состояние операции». [Реальные снимки](ru/widgets/feedback.md#shot-feedback-desktop).

| Виджет | Назначение и начальное состояние |
| --- | --- |
| `Alert(text)` | Постоянное информационное сообщение; `setSeverity` выбирает INFO, SUCCESS, WARNING или ERROR |
| `FieldError(text)` | Постоянная ошибка конкретного поля; начальная важность ERROR |
| `EmptyState(text)` | Пустой список; необязательная кнопка добавляется как дочерний `Section` |
| `Busy(text)` | Ожидание с неопределённым прогрессом; наследует контракт Progress |
| `Progress(text)` | Одна операция, сначала неопределённый прогресс; от 0 до 100 через `setPercentage`, −1 возвращает неопределённый режим |
| `Toast(capacity, dismissCaption)` | Ограниченная очередь уведомлений в потоке страницы, без перекрытия других элементов |

## Сообщение и ошибка поля

```java
var saved = new Alert("Изменения сохранены");
saved.setSeverity(Feedback.Severity.SUCCESS);
var error = new FieldError("Введите адрес электронной почты");
editor.setAccessibleError(error);
editor.setValidState(false);
var empty = new EmptyState("У вас нет активных заказов");
var retry = new Button("Повторить");
retry.onClick(event -> reloadOrders());
empty.add(new Section(retry));
```

`setText` меняет сообщение, `setSeverity` — оформление и доступную роль.
Ошибка не скрывается по времени. Видимость и признак invalid редактора
контролирует приложение; для удаления сообщения можно очистить текст,
скрыть или утилизировать виджет. `FieldError` не запускает валидацию и не
заменяет автоматически встроенные ошибки `FormField`.

Сообщения допускают дочерние блочные виджеты (например, `Section` с кнопками).
Базовые свойства Panel относятся к внешнему контейнеру; семантическое
оформление находится во внутреннем `.widgets-feedback`. Для темы можно
переопределить CSS `.widgets-feedback-info/success/warning/error`.

## Операция, прогресс и отмена

```java
var progress = new Progress("Загрузка фотографий");
progress.onCancel("Отменить", "Загрузка отменена", () -> job.cancel(true));
progress.setPercentage(40);
// Из фонового обработчика:
root.execute(() -> {
    if (progress.isRunning()) {
        progress.finish("Фотографии загружены", Feedback.Severity.SUCCESS);
    }
});
```

Виджет представляет одну операцию, но не создаёт потоки и не владеет задачей.
`onCancel` настраивается один раз до завершения. Нажатие сначала переводит
операцию в конечное состояние, выключает кнопку, освобождает callback и
только затем вызывает его. Callback должен быстро запросить кооперативную
отмену; остановку IO/вычислений обеспечивает приложение. Повторное событие
не вызывает отмену снова. Отключённая кнопка остаётся на месте.

`finish` завершает успехом, ошибкой или сообщением об отмене; повторный
`finish` не перезаписывает результат. Даже 100% само по себе не завершает
операцию. Изменение процента после завершения запрещено. Для повтора создайте
новый экземпляр; не применяйте запоздалые результаты к новой операции.
`dispose` освобождает обработчик отмены и завершает жизнь виджета, но не
отменяет внешнюю задачу: при необходимости добавьте собственный `onRetire`.
Все изменения из фоновых потоков выполняйте через `root.execute` и обычный
контракт жизненного цикла страницы.

## Очередь Toast

```java
var notifications = new Toast(3, "Закрыть уведомление");
boolean accepted = notifications.offer("Изделие добавлено", Feedback.Severity.SUCCESS, 5000);
notifications.offer("Не удалось сохранить заказ", Feedback.Severity.ERROR, 5000);
```

- Вместимость 1–20; при заполнении `offer` возвращает false, не вытесняя
  старые сообщения. Приложение должно обработать отказ (например, показать Alert).
- Текст непустой, максимум 8192 кодовых единицы UTF-16. Время жизни — 0
  (постоянно) либо 1000–86400000 мс. Для ERROR срок всегда постоянный,
  независимо от переданного допустимого времени.
- Кнопка закрытия отправляет серверу идентификатор только этого уведомления.
  Проверяются тип виджета, подписка, видимость, точная структура события
  и принадлежность идентификатора очереди. `dismiss(id)` и `clear()` дают
  приложению явное управление, в том числе постоянными ошибками.
- Повторная доставка состояния не создаёт второй Toast, не перезапускает
  таймер и не возвращает уже закрытый. Новые сообщения сохраняют порядок.
- Браузер удаляет просроченный Toast по таймеру. Если его кнопка имеет фокус,
  автоматическое скрытие откладывается до ухода фокуса. Сервер очищает
  просроченные записи лениво при `offer`/`getCount`; их число всегда ограничено.
  Серверных потоков и таймеров для каждой записи нет.
- При временном отсоединении дерева таймер останавливается; после возврата
  применяется исходный срок. `dispose` отменяет таймер и удаляет обработчики.
  Очередь принадлежит странице, не сохраняется между новыми сеансами.

## Доступность и проверка

ERROR получает `role="alert"`, остальные сообщения — `role="status"`;
содержимое атомарно. Изменение только процента не переписывает сообщение,
сохраняет его DOM-узел и не инициирует повторное объявление текста. У Progress
нативный именованный `progress`; неопределённый режим не имеет `value`.
Создание/обновление сообщений не вызывает focus. Кнопки доступны с клавиатуры
и через touch. Цвет дополняет смысл текста, не заменяет его.

Java проверяет границы, конечные состояния, однократную отмену, срок жизни,
вместимость, dispose и валидацию событий. JS проверяет текст без HTML,
стабильность DOM, таймеры и очистку. E2E в Chromium/WebKit проверяет
загрузка → пусто/ошибка/данные, повтор, отмену, закрытие, сроки и фокус
на 1280 и 390 px, а также axe для нового семейства.
