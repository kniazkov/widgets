## Регрессия

На базе `3702d1a` отдельно выполнен сценарий
`UploadResourcesTest.releasesCompletedContentAfterCallback`: десять файлов по 64 KiB,
приложение удерживает дескрипторы и результаты после callback. Из фикстуры удалён
только вызов нового cleanup API, отсутствующего в старой версии. Тест воспроизводит
дефект: `Resource cleanup did not finish`, 1 failure. На исправленной версии он проходит.

Девять новых Java-тестов проверяют освобождение данных и потоков, квоты, TTL и размер
кеша подтверждений, точное сравнение повторного чанка, ошибки обработчиков, прерванные
и неверные загрузки, detached loader, файловое копирование, восемь конкурентных клиентов,
четыре работающих и два ожидающих callback, фоновую уборку без запросов клиента.
Тест disposal обнаружил и помог устранить запуск ожидающих callbacks при закрытии корня.

В E2E проверены прогресс 50%, отмена, следующий файл, потеря конечного ответа и точный
повтор после окончания обработки. Потеря ответа имитируется на границе доставки XHR:
настоящий запрос с файлом доходит до Java, первый ответ заменяется сетевой ошибкой
для клиента, второй остаётся настоящим. Это важно для WebKit: Playwright route.fetch
получает multipart-тело без байтов файлов. Первые попытки такого перехвата дали отказ
сервера и не засчитывались как успешная проверка.

JS-тест дополнительно проверяет удаление ссылок на браузерные File и остановку таймеров
при disposal. Существующие проверки протокола и полноцепочечной загрузки сохранены.
