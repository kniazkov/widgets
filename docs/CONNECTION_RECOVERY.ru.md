# Восстановление соединения Widgets

Тайм-аут, обрыв сети, HTTP 408/429 или неподтверждённый HTTP 5xx не делают страницу
неисправной. Браузер не повторяет HTTP-запросы сам по себе. Повтор планирует владелец
операции: открытие страницы, синхронизация или бинарная загрузка. На запрос отведено
10 секунд; пауза между повторами растёт экспоненциально, меняется случайно и не превышает
15 секунд. При offline синхронизация не отправляет запрос; событие online будит тот же
очередной повтор, а не запускает параллельный. После нескольких неудачных попыток
виден существующий экран **Connection Terminated**. Корректный ответ убирает его.

Пока сервер знает страницу, черновик поля, URL и история остаются на месте.
Событие считается принятым только после ACK с его исходным идентификатором. Например,
если кнопка уже увеличила счётчик, но прокси вернул 504 вместо ответа, браузер
отправит прежний идентификатор, а сервер подтвердит его без повторного вызова
обработчика. Если экземпляр страницы потерян, Widgets заново запрашивает снимок
того же URL и не переносит неопределённые события в новый экземпляр. Локальные
несохранённые значения в этом случае могут быть потеряны. Это не сквозная гарантия
транзакции в сторонней системе: при внешних вызовах прикладному коду всё ещё нужны
собственные ключи идемпотентности.

HTTP 401/403 без подтверждённого истечения сессии останавливает повторы.
Если Widgets сообщает, что транспортная сессия истекла, вкладка один раз заново
загружает документ для получения новой сессии, без восстановления отозванного
клиента, привилегий и очереди старого документа. Повторное истечение до успешного
старта не перезагружает страницу снова. HTTP 426/505, неизвестная версия протокола или ошибка,
явно помеченная сервером как прикладная, тоже останавливают повторы. На существующем
экране **Client Error** атрибут `data-reason` различает `access`, `session`,
`protocol` и `application`; тело ответа прокси и внутренняя ошибка сервера
пользователю не выводятся.

Совместимость: успешные ответы текущего сервера объявляют
`X-Widgets-Protocol-Version: 1`; отсутствие заголовка допустимо для прежней версии
сервера. Сервер помечает ошибку обработчика
`X-Widgets-Protocol-Error: application`. Сам по себе код 500 от прокси
не считается приложенческой ошибкой. Изменений внешнего вида экранов нет.
