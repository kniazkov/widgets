# Перенос существующих виджетов

У виджета один структурный родитель. Передайте уже добавленный виджет в
`destination.add(widget)`, `destination.put(widget)` или
`destination.insertRow(index, row)`, чтобы перенести его без явного `remove()`.
После операции прежний контейнер больше не содержит виджет, а новый хранит его
на запрошенной позиции. В одной открытой странице браузер переносит тот же DOM-узел:
локальные значения и подписки сохраняются. В браузерах без нативного
`moveBefore()` порядок и значения сохраняются, но браузер может сбросить фокус
или перезапустить браузерные эффекты самого узла.

Пример: действие перемещает блок с полем, не пересоздавая его или подписки.

```java
final Section form = new Section(new InputField());
final Panel source = new Panel(form);
final Panel destination = new Panel();
final Button move = new Button("Перенести форму");
move.onClick(event -> destination.add(form));
root.add(new Section(move));
root.add(source);
root.add(destination);
```

В приложении отключите действие после переноса или проверяйте текущего родителя
перед повтором. Обычное добавление дубликата выбрасывает
`IllegalArgumentException`; у `SortableSection` и декораторов повторная передача
того же ребёнка остаётся бездействием. Слот декоратора заменяет старое содержимое;
при переносе его ребёнка наружу в прежнем слоте появляется пустой виджет.
`Table.insertRow` принимает перемещаемую строку из другой таблицы и проверяет
индекс до изменений. `Column.add` добавляет строку в свою таблицу с ячейкой
на позиции столбца; фактический родитель ячейки — строка, не столбец.

Самовложение, циклы, корни как дети, удалённые через `dispose()` экземпляры,
некорректные типы и перенос уже экспортированных виджетов в другой браузерный
корень отклоняются. Для другого корня создайте новый экземпляр виджета, при
необходимости используя те же модели. Новые, ещё не экспортированные виджеты
можно перестраивать во время подготовки страницы. Стандартные контейнеры
проверяют операции до изменения дерева; контракт действует в рамках обычного
потока событий Widgets, а пользовательские переопределения контейнеров должны
сохранять этот контракт. `remove()` по-прежнему означает временное отсоединение,
а не перенос; пустой контейнер после `removeAll()` не гарантируется для
декораторов с обязательным содержимым. Отдельные вызовы в `addAll()` выполняются
по очереди, не как единая транзакция.

Интеграционный пример для запуска и ручной проверки: `/widget-reparenting` на
сервере E2E. Введите текст, нажмите **Move to destination**, затем **Dispose
source** и **Moved action**. Поле остаётся после метки назначения с введённым
текстом, исходная метка исчезает, счётчик действия увеличивается. Для
таблицы нажмите **Reject table cycle** до и после **Move table cell**: при отказе
число строк не меняется, а допустимая операция переносит исходную ячейку во второй
столбец новой строки.
