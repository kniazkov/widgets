# DateField, TimeField и DateRange

`DateField` редактирует `LocalDate`, `TimeField` — `LocalTime` с точностью
до минуты. `DateRange` содержит два подписанных DateField и представляет
включительный диапазон `[start, end]`. Ни один из них не подставляет дату
«сегодня», часовую зону или UTC-полночь вместо отсутствующего значения.

## Типы, пустота и валидация

| Виджет | Java-значение | Текст в протоколе и Form |
| --- | --- | --- |
| DateField | `LocalDate`, годы 0001–9999 | `uuuu-MM-dd` |
| TimeField | `LocalTime`, секунды и наносекунды равны нулю | `HH:mm`, 00:00–23:59 |
| DateRange | `DateRange.Interval(start, end)` | Два поля: `<name>.start`, `<name>.end` |

`getValue()` возвращает `Optional`: пустой для пустого **и** ошибочного ввода.
Различить их позволяет `getValueModel().isValid()` и канонический `getText()`.
При ошибке модель не возвращает последнее корректное значение. Например,
`2027-02-29` остаётся ошибкой, а не превращается в 1 марта.

У DateField/TimeField модель имеет тип `TemporalModel<LocalDate/LocalTime>`
и реализует `Model<TemporalValue<T>>`. `TemporalValue.empty()` явно обозначает
отсутствие, `TemporalValue.of(value)` — наличие. `value()` у обёртки возвращает
Optional. В модели нет sentinel-даты, публичного null или `Optional`-поля.

```java
final TemporalModel<LocalDate> model = TemporalModel.dates();
final DateField date = new DateField(model);
date.setBounds(LocalDate.of(2028, 1, 1), LocalDate.of(2028, 12, 31));
date.setValue(LocalDate.of(2028, 2, 29));
// Обычная очистка без подстановки сегодняшней даты:
date.clear();
```

`setValue` и типизированный `setData` отклоняют значения вне границ или
поддерживаемой точности исключением, не изменяя предыдущее состояние.
`setText`/`textModel().setData` сохраняют ошибочный ввод, чтобы Form могла
показать ошибку; прикладной код не должен использовать raw-текст вместо
проверенного типизированного значения.

Min/max включительны, задаются атомарно через `setBounds(min, max)`.
Для одной границы или снятия ограничений доступна модель:

```java
model.setBounds(TemporalValue.of(LocalDate.of(2028, 1, 1)), TemporalValue.empty());
model.setBounds(TemporalValue.empty(), TemporalValue.empty());
```

Смена границ заново проверяет текущее значение, уведомляет подписчиков
и обновляет нативные атрибуты браузера, но не обрезает введённое значение.
Min > max запрещено. Для времени диапазон через полночь не подразумевается:
18:00–09:00 отклоняется, его нужно моделировать отдельным прикладным правилом.

Модель можно передать нескольким полям; обновления синхронизируются.
Мутации UI и модели выполняются в контексте страницы, при внешнем завершении —
через `root.execute`. Замена текстовой модели через `setTextModel` на произвольную
строковую модель запрещена: иначе потеряется типизированная валидация.
При dispose виджет снимает свои подписки; заимствованная модель остаётся пригодной.

## FormField, Enter и диапазон

```java
final Form form = new Form("Доставка", "Сохранить");
final DateField date = new DateField();
final FormField day = new FormField("deliveryDate", "Дата доставки", date);
day.setRequired(true);
day.setConstraintMessages("Укажите дату.", "Проверьте дату и её границы.");
day.setHelp("Календарная дата доставки без часового пояса.");
form.addField(day);

final TimeField time = new TimeField();
time.setBounds(LocalTime.of(9, 0), LocalTime.of(18, 0));
form.addField(new FormField("deliveryTime", "Время доставки", time));

final DateRange period = new DateRange("period", "Начало периода", "Конец периода");
period.setErrorMessage("Заполните обе даты: начало не позже конца.");
form.addDateRange(period);
```

Используй именно `form.addDateRange(period)`: он регистрирует два поля
в снимке отправки, подключает серверную проверку start ≤ end, ошибки возле
полей и фокус на первом неверном поле. Имена должны быть уникальны, включая
`period.start`/`period.end`; prefix ограничен правилами имени FormField
(вместе с суффиксом максимум 64 символа). Уже присоединённый или повреждённый
диапазон зарегистрировать нельзя. Для удаления всего диапазона — `period.remove()`.

Две пустые даты означают необязательный отсутствующий диапазон. Одна пустая —
ошибка. Одинаковые начало и конец допустимы: это один включённый день.
Неверные даты и границы сначала проверяются самими редакторами, затем порядок.
Чтобы сделать диапазон обязательным, вызови `setRequired(true)` у обоих
`getStartField()`/`getEndField()`. Обязательность — ограничение FormField,
а не самого типизированного агрегата.

`getValueModel()` диапазона — read-only наблюдаемый агрегат. Для изменения
используй `getStart()` и `getEnd()`. `getValue()` возвращает Interval только
при наличии обоих принадлежащих диапазону, корректных, упорядоченных значений.
У отдельно стоящего DateRange валидность можно читать из агрегата; показ ошибок
при отправке обеспечивает Form. Disabled-поля не входят в снимок Form;
проверка порядка выполняется только когда в снимке есть оба конца.

Все обычные настройки InputField/FormField сохраняются: label/help/error,
required, readonly, disabled, Tab и серверный Enter. Нативный календарь или
выбор времени может сам обрабатывать клавиши, пока открыт. Подтверждение
формы кнопкой использует ту же серверную валидацию.

## Нативный выбор и локаль

В браузере это настоящие `<input type="date">` и `<input type="time" step="60">`.
Календарь, выбор времени и порядок сегментов принадлежат браузеру/ОС. Виджет
не реализует второй календарь и не обещает одинаковую картинку на Windows,
Linux, Android и iOS. Ввод возможен клавиатурой; средства выбора доступны там,
где они поддерживаются браузером.

`setLocale(Locale.forLanguageTag("ru"))` или `setLocale(Locale.US)` задаёт
`lang` и локаль серверного `formatValue()`. Нативный редактор вправе предпочесть
язык браузера/ОС: в облачном Chromium даже при `lang="ru"` показан формат
MM/DD/YYYY и AM/PM. Если нужен строго одинаковый российский формат внутри
редактора на всех платформах, этот нативный вариант такого обещания не даёт.
Подписи и сообщения задаёт приложение. `formatValue()` возвращает SHORT-формат
Java для настроенной локали; это полезно для отдельного текстового представления.

Канонический текст и значение не меняются при смене локали и зоны браузера.
В JS не используется `Date`, timestamp, `valueAsDate` или преобразование в UTC.
Незавершённый нативный ввод часто имеет `value=""` и `validity.badInput=true`;
клиент передаёт служебный текст `?`, который сервер считает ошибкой. Эхо этого
маркера не стирает незавершённые сегменты. Обычное очищение передаёт `""`.
Произвольную неверную строку, заданную сервером, нативный input показать не может;
она остаётся в модели и отклоняется серверной проверкой.

## Instant, зона и DST

LocalDate и LocalTime ещё не задают момент времени. Для преобразования у DateField
есть явный `toInstant(time, zone, offset)`:

```java
final Optional<Instant> instant = date.toInstant(
    LocalTime.of(12, 30), ZoneId.of("Europe/Moscow"), ZoneOffset.ofHours(3));
```

Метод использует `ZonedDateTime.ofStrict`: несуществующее локальное время в DST-gap
отклоняется. В DST-overlap приложение обязано явно выбрать одно из допустимых
смещений; неподходящее смещение тоже отклоняется. Пустая/неверная дата возвращает
пустой Optional. Автоматического переноса через gap или выбора «первого» offset нет.
Сам DateRange календарный: он не означает диапазон фиксированных 24-часовых суток.

пустые поля, високосная дата, disabled, min/max, ошибка порядка и успешная отправка.
