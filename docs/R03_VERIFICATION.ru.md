## Воспроизведение и покрытие

Регрессионный `EventAcknowledgementTest.acknowledgesRemovedTarget` отдельно запущен
в изолированном checkout базы `b8a9693`. Он **упал на исходной ошибке**: ожидался ACK
`#1`, получен `#?`. На исправленном коде этот тест проходит.

Шесть новых Java-тестов проверяют:

- удаление адресата до единственного события;
- смешанный пакет applied/rejected/obsolete, удаление предыдущим контроллером,
  повтор того же ID в пакете и повтор всего пакета;
- повреждённый конверт с корректным ID и следующий допустимый клик;
- повреждённую/убывающую последовательность без частичного исполнения;
- исключение после прикладного побочного эффекта без повторного вызова;
- два настоящих клика и повторную доставку после потери ответа через реальный HTTP.

JavaScript-тесты проверяют снимок очереди, новые события во время запроса, частичный ACK,
сброс счётчика после прогресса, задержки 250/500 мс, предел в три запроса, потерянный
ответ с задержкой 2500 мс, общий запрет обхода задержки через polling/ввод/callback,
повреждённый/убывающий/опережающий ACK, запрос resync сервером, отмену таймеров и
игнорирование поздних ответов после disposal.

Три новых E2E-сценария выполняются в обоих браузерах:

1. Java удаляет кнопку, первый ответ удерживается; браузер успевает отправить второй
   клик этой кнопки и допустимое действие. Второй пакет получает obsolete/applied,
   очередь освобождается, повторного потока событий нет.
2. Сервер исполняет клик, его ответ обрывается; двойной клик сохраняет два действия,
   повторный пакет не вызывает первый контроллер снова, следующий клик работает.
3. ACK трёх ответов заменяется на `#?`: проверяются задержки, ровно три запроса
   старого действия, одно пересоздание страницы, сохранение URL/query и TabContext,
   отсутствие повторного бизнес-эффекта и работоспособность следующего клика.
