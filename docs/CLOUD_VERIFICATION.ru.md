# Проверка Widgets на облачном компьютере — 11.11.2026

Проверена ветка `docs/review-roadmap-2026-11`, основанная на
`7112edfa10eea3f3f895e426895242f432eba41e`, с дополненным AllWidgets.
Точный хеш исходника демонстрации сохранён в [manifest.json](images/widgets/manifest.json).

демонстрации существующих компонентов. Дефекты из ревью здесь не объявляются исправленными.

## Среда и способ запуска

- Linux облачного компьютера; Temurin JDK **21.0.13+9**, Maven **3.9.9**.
- Node.js **24.22.1**, Playwright **1.62.1**, системный Chromium **156.0.8078.79**.
- У Maven настроен proxy этой среды и системное хранилище доверенных сертификатов.
  Проверка TLS не отключалась. Сами proxy-настройки не являются частью репозитория.
- Сервер AllWidgets запущен из `target/classes` с собранными runtime-зависимостями на
  порту **18087**. Необязательный аргумент порта добавлен, потому что стандартный 8080
  на облачном компьютере занят.
- Для E2E запущен `com.kniazkov.widgets.e2e.E2ETestServer` на свободном loopback-порту,
  выставлен `WIDGETS_E2E_BASE_URL`, Playwright использовал исходные тесты репозитория.
  Временный конфиг наследовал `playwright.config.js`, заменяя список проектов на один
  Chromium с `executablePath: "/usr/bin/chromium"` и аргументом `--no-sandbox` для
  изолированной тестовой среды. Утверждения тестов не менялись и тесты не исключались
  внутри Chromium-проекта. Это **не** рекомендация запускать производственный браузер
  без sandbox.
- Результат E2E runner проверялся по exit code процесса тестов: **0**. Предыдущие неудачные
  попытки из-за недоступного локального proxy, неполного classpath и порта не засчитаны.
  После исправления окружения выполнен полный повторный прогон Chromium.

Стандартный воспроизводимый путь вне ограничений данной среды:

```bash
npm ci
npx playwright install --with-deps chromium webkit
mvn verify
npm run test:browser
./run.sh com.kniazkov.widgets.example.AllWidgets 18087
```

Установка всех браузеров обязательна для штатного `npm run test:browser`.
Облачный fallback с системным Chromium — отдельная проверка, не замена штатного gate.

## Что проверено в интерфейсе

- Галерея открывается и показывает поля normal/filled/invalid/disabled, кнопки,
  выборы, изображения, таблицы и контейнеры.
- `MessagePopup`, обычный `Popup` и `ModalPopup` открываются и закрываются своими кнопками.
  Сняты открытые окна, а не только их кнопки запуска.
- `SuggestionField`: список раскрывается, ArrowDown/Enter выбирают значение; значение
  отображается в поле. Сохранён кадр раскрытого списка.
- `Countdown`: кнопка перезапуска задаёт 20 минут через сервер; истёкший таймер показывает
  `00:00`. Отсчёт продолжается в браузере.
- `Carousel`: drag переключает слайд 1→2; серверный обработчик меняет подпись на
  `Selected image: 2`. Сохранены начальное состояние и результат.
- В автоматических Chromium E2E пройдены narrow/mobile viewport, touch/pointer,
  загрузка с повтором чанка, скачивание, история Back/Forward, разрыв соединения,
  modal dismiss, suggestions/keyboard и tab context.

Отдельный ручной просмотр **всего** AllWidgets на мобильном устройстве и проверка экранным
диктором здесь не заявляются. Эти сценарии остаются явными критериями соответствующих
задач. Наличие снимка не означает доступности виджета: известные проблемы описаны в
R09–R11 и других пунктах [чеклиста](REVIEW_CHECKLIST.ru.md).

## Изображения и контроль покрытия

[Визуальный каталог](WIDGET_GALLERY.ru.md) связывает каждый конкретный класс с изображением.
Row/Cell видны в Table, базовые контейнеры — в композиции. Невизуальные и абстрактные
сущности перечислены отдельно. Все 34 crop проверены визуально после вырезки.

`npm run check:gallery` сверяет публичные классы исходников с manifest, проверяет наличие
PNG, их SHA-256 и подключение в Markdown. Проверка включена в `npm run test:browser`.
Она контролирует полноту и целостность файлов; смысл снимка и корректность состояния
по-прежнему требуют визуальной проверки.
