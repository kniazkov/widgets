# UploadManager и UploadList

`UploadManager` — кнопка выбора нескольких файлов с серверным контролем ограничений.
`UploadList` — отдельный блочный список этих файлов. Оба виджета нужно добавить в один
`RootWidget`; у каждого менеджера должен быть свой список. Пример находится в `AllWidgets`.

```java
final UploadList list = new UploadList();
final UploadManager manager = new UploadManager("Выбрать файлы", list,
    10, 2 * 1024 * 1024, (key, file) -> {
        // Обработать file; сохранять результат идемпотентно по key.
        // Потоковые данные действительны только до выхода из callback.
    });
manager.setAcceptedFiles(".txt,.pdf,image/*");
root.add(new Section(manager));
root.add(list);
```

## Состояния и управление

| Состояние | Значение | Действия |
| --- | --- | --- |
| `queued` | Файл зарегистрирован, ожидает свободного слота передачи | cancel, remove |
| `uploading` | Передаются бинарные чанки | cancel, remove |
| `processing` | Передача окончена, сервер обрабатывает файл | cancel, remove |
| `done` | Обработчик успешно завершился | remove |
| `error` | Ошибка проверки, передачи или обработки | retry для восстанавливаемой ошибки, remove |
| `cancelled` | Загрузка отменена | retry после завершения старого обработчика, remove |

Индивидуальный прогресс показывает подтверждённые сервером байты; во время обработки
индикатор неопределённый. Общий процент взвешен по размерам файлов в списке; это прогресс
передачи, а не обработки. Отдельный счётчик показывает число успешно обработанных файлов.
Удаление строки меняет знаменатель. Нулевые файлы поддерживаются.

Кнопки остаются теми же DOM-элементами при обновлении прогресса, поэтому обновление между
нажатием и отпусканием мыши не теряет клик. Есть доступные имена кнопок и progress,
статус списка объявляется через `role=status`. На узком экране строка переносится.

## Ограничения и безопасность

- `maxFiles`: 1–100 строк, включая завершённые и ошибочные; remove освобождает место.
- `maxBytes`: лимит одного файла. Дополнительно действуют `Options.maxFileSize` и общие
  квоты/срок жизни upload-протокола. Это не новая независимая очередь исполнителей.
- `setAcceptedFiles`: расширения, MIME-типы и маски `image/*`, разделённые запятыми.
  Проверяется сервером. MIME и имя присылает клиент; это **не проверка содержимого**.
- Ошибка одного файла не останавливает остальные. Потеря ответа вызывает повтор чанка
  штатным транспортом. Последний чанк не вызывает обработчик повторно в той же попытке.
- Retry создаёт новый номер попытки, сохраняя ключ логической операции и одну строку.
  Ключ передаётся в `Processor.process`. **Приложение обязано сохранять результат
  идемпотентно по этому ключу**, например через уникальный ключ транзакции в хранилище.
  Библиотека не может откатить внешние эффекты обработчика, успевшего записать результат.
- Cancel прерывает серверный callback. Если сторонний код игнорирует interruption,
  retry станет доступен только после выхода из него; параллельного повтора не будет.
- Remove удаляет строку и отменяет текущую работу, но не удаляет уже сохранённый результат.
- Временный `UploadedFile` нельзя хранить после callback. Для сохранения скопируй данные
  в своё хранилище до возврата. Из фонового обработчика нельзя напрямую изменять виджеты.
- В браузере `File` сохраняется для retry до done/remove/уничтожения страницы. После
  перезагрузки страницы очередь не восстанавливается. Пауза/возобновление между сессиями
  и распределённое exactly-once выполнение не входят в контракт.
- `onSelect` менеджера заменять нельзя: обработчик задаётся конструктором. Обычный
  `FileLoader` и его API продолжают работать без изменений.

В `AllWidgets` доступны `.txt` и `.bin`, до 10 файлов по 2 MiB. Файл с именем,
начинающимся на `retry`, намеренно получает одну ошибку обработки; повтор завершается
успешно. Это демонстрационное поведение, а не правило библиотеки.

## Проверки

`UploadManagerTest` проверяет лимиты, отмену, защиту от поздних чанков, повтор последнего
чанка, стабильный ключ retry и запрет параллельного повтора при отмене обработки.
`upload-manager.test.js` проверяет очередь, состояния, освобождение ссылок, локальные
лимиты, нулевые файлы. `upload-manager.spec.js` проверяет реальную загрузку, ошибки,
потерю ответа, отмену и повтор в Chromium и WebKit.

Для повторного получения иллюстраций:

```sh
WIDGETS_CAPTURE_UPLOADS=1 npm run test:e2e -- upload-manager.spec.js --project=chromium
```

Результаты: `target/upload-gallery/chromium`. PNG — настоящие полные снимки AllWidgets;
JSON рядом хранит viewport, scroll и прямоугольник карточки для последующей вырезки.
