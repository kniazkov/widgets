# Проверка R24: сообщения и состояние операций

Дата: 16 ноября 2026 года. База: `f0c3e1ce1be08650dc55f261e43f6fe3f28b0133`.
Проверена рабочая ветка с реализацией R24, тестами и документацией.

## Среда и сборка

Облачная Linux-среда Debian 13, Temurin JDK 21.0.13, Maven 3.9.9,
Node.js 24.22.1, Playwright 1.62.1. Зависимости установлены через `npm ci`.
`mvn -o verify` завершился успешно: **606 Java-тестов**, ноль ошибок,
ноль замечаний Checkstyle. Offline использовался после первоначальной загрузки
Maven-зависимостей; этапы сборки и проверки не исключались.

В облачной среде нет прав на системную установку WebKit-зависимостей.
Недостающие библиотеки получены из официального Debian-репозитория и
распакованы в локальный каталог браузера. Chromium и WebKit загружены с
официальных адресов Playwright/Chrome for Testing. Проверка наличия библиотек
через системный ldconfig отключена только в локальном окружении
(`PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1`), поскольку она не видит
локальную установку. Сами браузеры действительно запускались; тесты,
assertions и настройки CI не отключались и не ослаблялись.

## Автоматические сценарии

- `npm run check:js`: ESLint и Prettier проходят.
- `npm run test:js`: **246 тестов**, все проходят.
- `npm run check:gallery`: покрытие **53 конкретных классов виджетов**;
  проверены файлы, ссылки, alt, SHA-256, размеры и границы вырезок.
- Java: границы −1/0/100, отказ для неверных процентов и позднего прогресса,
  конечные состояния, однократная отмена и освобождение callback при dispose,
  вместимость Toast, истечение срока без удаления ошибки, валидация
  идентификатора и точной структуры события закрытия.
- JS: текст не становится HTML; прогресс сохраняет DOM-узел сообщения;
  повторное состояние не перезапускает Toast и не возвращает закрытый;
  таймер очищается при detach/dispose; фокус на кнопке откладывает скрытие;
  старый обработчик после dispose не отправляет событие.
- E2E: Chromium и WebKit, ширины 1280/390 px. Загрузка → пустой результат,
  новый запуск → ошибка, прямой повтор → данные; отмена с выключением кнопки;
  успех Toast исчезает, ошибка сохраняется до явного закрытия; Enter и touch;
  фокус остаётся на кнопке запуска уведомления; новые блоки не переполняются.
  axe для `.widgets-feedback` не обнаружил нарушений.

Полный `npm run test:browser`: lint, форматирование, галерея и 246 JS-тестов
прошли; E2E — 196 прошли, два первоначально упали.
В первом полном прогоне два Chromium-сценария R24 запускали axe до появления
асинхронно построенной страницы. Добавлено ожидание видимого feedback-блока.
Повторный запуск `node scripts/run-e2e.mjs feedback.spec.js` на окончательном
тесте: **4/4 проходят**, включая axe и touch. Это исправление тестового
ожидания, а не исключение проверки доступности. После этого исправлен
прямой повтор в AllWidgets: после конечного состояния кнопка сама создаёт
новый экземпляр операции. Повторные `mvn verify` и все четыре E2E-сценария
на этом изменении также прошли. Начальный вид карточки на снимках не изменён.

## Визуальная и ручная проверка

Собранный `AllWidgets` запущен на облачном компьютере и открыт в облачном
Chromium. Проверены широкий экран и iframe шириной 390 CSS px:

- сообщение об успехе, предупреждение и ошибка различимы; длинный русский
  текст переносится, кнопки не обрезаны;
- Busy отображает неопределённый прогресс, Progress — 40% и кнопку отмены;
- мышью подтверждены отмена и ошибка; клавишей Enter — новый запуск и
  успешный повтор с серверными сообщениями «Найдено изделий: 2» и
  «Проверка завершена»;
- уведомление об ошибке сохраняется; создание сообщений не переводит фокус;
- роли и контраст проверены автоматикой; ручное прослушивание screen reader
  не проводилось. Touch проверен автоматическими E2E, не физическим телефоном.

Из настоящих скриншотов сделаны три PNG-вырезки без масштабирования и ретуши.
Они подключены в [каталог](WIDGET_GALLERY.ru.md#feedback); происхождение,
исходные размеры, координаты, SHA-256 AllWidgets и изображений — в
[manifest.json](images/widgets/manifest.json). До и после исправления
проверено, что базовые стили Panel больше не убирают оформление сообщений.
