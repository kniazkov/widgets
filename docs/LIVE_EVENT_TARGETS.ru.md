# Актуальное дерево при обработке пакета (R04)

События одного запроса выполняются в порядке их ID под блокировкой RootWidget.
Перед **каждым** событием сервер заново находит адресата в текущем дереве, затем
проверяет его корень, состояние предков и допустимость события по правилам R02.
Индекс и итератор не сохраняются между вызовами прикладных обработчиков.

Ранее карта адресатов строилась один раз до пакета. R02/R03 уже запрещали вызов
отсоединённого виджета через проверку корня, но карта всё ещё не видела узлы,
присоединённые предыдущим обработчиком. Теперь одиночный запрос и пакет используют
одинаковый поиск по актуальному дереву.

## Результаты изменений дерева

| Состояние к моменту обработки события | Результат |
| --- | --- |
| Адресат или его предок удалён | `obsolete / detachedWidget`, контроллер не вызывается |
| Поддерево заменено, событие содержит ID старого узла | `obsolete / detachedWidget`; событие не перенаправляется на замену |
| Новый адресат присоединён предыдущим обработчиком | Находится в текущем дереве; обычная проверка R02 и `applied` при допуске |
| Узел перенесён внутри корня | ID сохраняется; проверяются новые предки, включая hidden/disabled |
| Узел перенесён в другой корень | Старый канал получает `obsolete / detachedWidget` |
| Узел перенесён в текущий корень | До присоединения — obsolete; после — обычная проверка R02 |
| Узел удалён, затем возвращён | Новое событие может исполняться после возврата; старый потреблённый ID не оживает |
| Предыдущий обработчик отозвал TabContext | Остаток пакета не исполняется, ответ содержит `tabContextExpired` |
| Предыдущий обработчик отозвал BrowserSession | Остаток пакета не исполняется; HTTP 403 с `sessionExpired` |
| Предыдущий обработчик выбросил исключение | Пакет прерывается; уже выполненные эффекты не откатываются |

Терминальные applied/rejected/obsolete продвигают накопительный ACK согласно
[контракту R03](EVENT_ACKNOWLEDGEMENTS.ru.md). Устаревший адресат не мешает следующему
допустимому событию в том же пакете. Отзыв контекста имеет приоритет над продолжением
обычной обработки: необработанный остаток не объявляется успешно доставленным.

После прикладного исключения действует прежняя диагностика. ID первого обработчика
уже потреблён по R03; при повторной доставке он не выполняется снова. Оставшиеся
события проверяются относительно фактического дерева после исключения. Автоматическое
восстановление после произвольной ошибки приложения этим контрактом не обещается.

## Пример интеграции

```java
final Button old = new Button("Старое действие");
final Button replacement = new Button("Новое действие");
final Section holder = new Section(old);
final Button replace = new Button("Заменить");
replace.onClick(event -> {
    holder.removeAll();
    holder.add(replacement);
});
root.add(new Section(replace));
root.add(holder);
```

Если объединённый пакет содержит клик `replace`, затем клик `old`, затем действие
другой действующей кнопки, результат — `applied, obsolete, applied`. Новая кнопка
получает собственный ID: клик старой не превращается в клик новой. Событие, адресованное
новому ID после присоединения, проверяется как обычное событие текущего дерева.

При перемещении существующего узла сначала вызывай `widget.remove()`, затем
`destination.add(widget)`. Изменение родителя само по себе не является передачей
прикладных прав: их по-прежнему проверяет приложение. R04 не вводит общую транзакцию
или блокировку сразу нескольких RootWidget. Параллельные изменения разных деревьев
и бизнес-авторизацию нужно согласовывать на уровне приложения.

## Совместимость и стоимость

Публичный Java API и формат ответов R03 сохранены. Изменилось разрешение адресата:
пакет видит новое состояние дерева после каждого завершившегося обработчика.

Поиск имеет стоимость до O(E × V), где E — число событий, V — число виджетов. Это
осознанная замена снимка индекса на простой актуальный обход: типичный запрос содержит
одно событие, а постоянный индекс потребовал бы корректной инвалидации во всех
контейнерах. Квоты размера пакета относятся к R17; этот PR не добавляет нагрузочных
гарантий для произвольно больших пакетов и деревьев.

Изменение невизуальное: новые виджеты не добавлены, AllWidgets и снимки галереи не
меняются. Тестовый маршрут `/live-event-targets` демонстрирует замену дерева и счётчик
модели; он существует только в E2E-сервере. Облачная проверка описана в
[R04_VERIFICATION.ru.md](R04_VERIFICATION.ru.md).
