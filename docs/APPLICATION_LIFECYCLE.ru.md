# Жизненный цикл приложения и страницы

Один объект `Application` предназначен для одного запуска. `Server.start`
возвращает прежний интерфейс HTTP-сервера; его `stop()` закрывает и сервер,
и приложение. Можно закрыть само приложение через `Application.close()`:
оно также останавливает связанный HTTP-сервер. Повторное закрытие безопасно;
закрытый объект не запускается снова. Для рестарта на том же порту создайте
новое приложение с теми же настройками. Если слушатель не смог запуститься,
закрытие всё равно выполняется. Приложение, которое создали, но не запустили,
также нужно закрыть.

```java
try (var application = new Application((root, context) -> {
    root.add(new Section(new TextWidget("Ready")));
})) {
    final var options = new Options.Builder().setPort(8000).build();
    final var server = Server.start(application, options);
    try {
        // Runtime belongs to the caller; await the owner's shutdown signal here.
    } finally {
        server.stop();
    }
}
```

Порядок владения:

- Приложение владеет watchdog, клиентами, контекстами, пулом обработки
  загрузок и временными файлами. При закрытии контексты отзываются,
  новые операции не принимаются, запущенный вызов UI получает возможность
  закончить, после чего подписки и очереди уничтожаются. Загрузки
  отменяются, включая незавершённые и ожидающие обработки. Прерывание
  фоновой задачи не откатывает её уже выполненные внешние операции.
- Один клиент владеет одной страницей, в том числе пока она находится
  в кэше Back/Forward. Удаление из кэша уничтожает клиента и снимает
  его подписки, не отзывая соседние страницы или вкладки. Повторное
  открытие уничтоженной страницы создаёт новый экземпляр. Обычный
  `Widget.remove()` хранит подписки пригодного к повторному присоединению
  виджета; `Widget.dispose()` и закрытие страницы завершают их.
- Виджет снимает только свои подписки и локальные каскады стиля. Модель,
  переданная приложением или разделяемая несколькими виджетами, остаётся
  пригодной для других клиентов. Самостоятельные ресурсы Java регистрируйте
  через `root.onClose(...)` для страницы или `application.onClose(...)`
  для всего приложения, например `executor::shutdownNow`. Исключение
  одного обработчика записывается в серверный журнал и не препятствует
  остальным. Вызывайте остановку с управляющего потока владельца сервера,
  а не из контроллера виджета или задачи, которую остановка должна завершить.

Проверить поведение браузера можно на локальном тестовом `E2ETestServer`:
откройте `/application-lifecycle`, введите черновик, перейдите в монитор,
очистите кэш и проверьте счётчик освобождённых страниц. При возврате Back
должна открыться новая страница с пустым полем. Новых виджетов нет.
