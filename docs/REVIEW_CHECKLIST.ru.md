# Чеклист повторного ревью Widgets — 11 ноября 2026

План составлен по повторному ревью commit `7112edfa10eea3f3f895e426895242f432eba41e`. Порядок: P0 — изоляция клиентов; P1 — корректность, восстановление, ресурсы и доступность; P2 — полноценные прикладные интерфейсы и архитектура; P3 — расширения. Все зависимости ссылаются на более ранние задачи. Внутри одного приоритета можно выполнять независимые задачи параллельно.

По принятому процессу чекбокс отмечается в рабочей ветке при начале реализации и входит в тот же PR с кодом и тестами. Галочка в незалитой ветке означает «в работе»; завершение подтверждается слиянием PR и его проверками. Отдельный коммит только ради галочки не создаётся. R18/R19 уже начаты этой веткой: результаты и ограничения приведены в [облачной проверке](CLOUD_VERIFICATION.ru.md) и [визуальном каталоге](WIDGET_GALLERY.ru.md). Остальные пункты описывают будущую реализацию; этот PR их не исправляет.

## Обязательная приёмка

- Каждая задача включает конкретные автоматические тесты и проверку собранного проекта на облачном компьютере; jsdom не заменяет E2E в браузере.
- Каждый новый виджет описывается в документации и добавляется в AllWidgets. У всех новых и существующих видимых виджетов должны быть реальные изображения, вырезанные из скриншотов облачного компьютера и подключённые в документацию.
- Изменение внешнего вида требует обновления снимка. Для абстрактных/невизуальных сущностей отдельный снимок не нужен; исключение объясняется в матрице покрытия.
- Непрошедшие проверки и инфраструктурные блокеры указываются явно и не превращаются в выполненные критерии. В PR фиксируются SHA, команды, версии и результаты.

### R01. Привязать протокол к владельцу страницы и закрыть доступ по чужому clientId

**P0 · [Issue #105](https://github.com/kniazkov/widgets/issues/105)**. Зависимости: Нет предварительных задач.

F01. Идентификатор Client предсказуем и сам по себе открывает доступ к синхронизации и действиям. В ревью независимый HTTP-клиент без cookie, browserId и tabId получил обновления чужой страницы и вызвал её кнопку. Проверка существования TabContext не удостоверяет отправителя.

**Что сделать**

- Ввести проверяемую сервером принадлежность канала браузерной сессии и непредсказуемый секрет страницы/канала; browserId и tabId не считать авторизацией
- Применить единый контроль к sync, upload, kill, диагностике и скачиванию; сначала проверять владельца, эпоху и отзыв сессии, затем выполнять события
- Убрать изменение состояния через GET; определить CSRF/Origin-политику и запрет кеширования персональных ответов; не подменять этим бизнес-проверки прав в приложении
- Документировать создание, передачу, обновление и отзыв секретов, совместимость с Back/Forward, несколькими вкладками и reconnect; не писать секреты в URL и логи

### R44. Добавить клавиатурные события виджетов и действие по Enter

**P2 · [Issue #154](https://github.com/kniazkov/widgets/issues/154)**.

При вводе пароля нажатие Enter должно вызывать ту же попытку входа, что и кнопка «Войти», с актуальными значениями полей и той же серверной валидацией. Нужен общий API клавиатурных событий поддерживающих их виджетов, а не специальная логика только для пароля.

Приоритет: **P2**. Пункт **R44**, выполнять перед R20 / #124. Номера существующих пунктов не менять.

Связанные задачи: R20 / #124 использует этот механизм для Form; R31 / #135 — расширенная работа с IME и локальными действиями. Минимальная защита от отправки во время composition входит сюда и не откладывается на R31.

**Что сделать**

- Определить типизированное Java-событие и API подписки на клавиатуру (например, onKeyDown/onKeyUp и удобный onEnter). Указать перечень поддерживаемых виджетов: однострочные поля, пароль, многострочный ввод, поле подсказок; обосновать остальные. Публичные названия API согласовать со стилем библиотеки.
- Передавать только явно подписанные клавиши/комбинации. Для входа достаточно Enter; не отправлять на сервер каждый набираемый символ. Определить key, при необходимости code/location, модификаторы Ctrl/Alt/Shift/Meta, repeat и состояние composition. Не дублировать содержимое поля или пароль в клавиатурном payload и диагностике.
- Обеспечить порядок: последний ввод и соответствующее обновление модели применяются до серверного обработчика Enter, даже без blur, при debounce, быстрой печати и медленной сети. Обработчик кнопки и Enter вызывают одно прикладное действие; механизм не требует нового Form.
- Разделить физическое событие клавиши и логическую отправку. Обычный Enter и NumpadEnter запускают действие один раз за нажатие; автоповтор при удержании не создаёт повторных попыток. - Очищать подписки при окончательном удалении/disposal; восстановление страницы из кеша не должно удваивать обработчики. Не ломать существующую клавиатурную работу виджетов.
