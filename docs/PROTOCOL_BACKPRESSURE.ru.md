# Ограничение очередей протокола

Лимиты применяются независимо к каждому экземпляру страницы. Очередь
накопленных DOM-изменений до отправки и окно уже сформированных, но ещё
не подтверждённых обновлений не могут расти бесконечно. Бюджеты можно
передать через `Options.Builder.setProtocolLimits(ProtocolLimits)`.

| Граница | По умолчанию |
| --- | --- |
| Буфер черновых изменений и окно replay | каждое до 32 768 записей и 24 МиБ сериализованных изменений |
| Ответ сервера | до 1024 записей и 8 МиБ объектов обновления, без остального JSON-конверта |
| Возраст неподтверждённого обновления | до 60 секунд при следующем обращении к отдельному окну replay |
| Запрос с событиями | до 64 событий и 512 КиБ UTF-8; браузер получает лимиты при создании |
| Локальный буфер ещё не подтверждённого ввода | до 256 записей, 512 КиБ и 120 секунд при попытке синхронизации |

Сервер отправляет последовательные ограниченные пакеты. Клиент может
подтвердить только уже переданный номер в текущем epoch. При повторе
используется тот же сформированный пакет, а подтверждения не отматывают
окно назад. Сжатие разрешено только для соседних ещё не отправленных
назначений одного визуального свойства (цвет, фон или прозрачность) тому
же виджету в том же состоянии. Два назначения текста, команды построения
дерева и любые пользовательские действия не объединяются.

При превышении ёмкости или срока неполное состояние не применяется.
Активная страница создаёт новый серверный экземпляр и получает новый
снимок состояния, уже сохранённого приложением; старые клики не
повторяются. Если не помещается сам начальный снимок, браузер сообщает
об ограничении вместо бесконечных перезапусков. Потерянные локальные
несохранённые данные реконструировать нельзя. При переполнении очереди
ввода браузер останавливает её и показывает явное сообщение; автоматической
повторной отправки таких действий нет. Приложение по-прежнему отвечает
за долговременное сохранение бизнес-операций.

Кэш Back/Forward по-прежнему ограничен числом записей и возрастом, и
просроченные скрытые страницы освобождаются также при открытой вкладке.
Просроченная версия страницы не возвращает браузеру старый DOM. Счётчики
отказа содержат только вид лимита, глубину/байты окна и объём повторных
отправок, не значения свойств, секреты или пользовательский ввод.

Для проверки используйте страницу `/protocol-backpressure` тестового
`UploadBoundaryServer`. «Save normally» меняет счётчик без пересоздания
страницы. «Save and refresh under pressure» делает один сохранённый
шаг, затем создаёт обычный конечный поток изменений при малом тестовом
бюджете. Новый номер снимка и увеличение счётчика ровно на один
подтверждают восстановление DOM без повтора. Новый виджет не добавлен.
