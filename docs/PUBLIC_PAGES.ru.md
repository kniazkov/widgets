# Публичный HTML до JavaScript

`PublicPage` — явное дополнение к обычному `Page`. Оно позволяет показать публичный
каталог, описание товара или длинный текст уже в HTTP-ответе. Ссылки и изображения
работают при выключенном JavaScript. Это не утверждение о неспособности поисковиков
исполнять JS и не обещание индексации.

## Контракт и пример

Рабочий пример: `com.kniazkov.widgets.example.PublicCatalog`. Запусти его из IDE после
`mvn verify`, открой `http://localhost:8000/public-catalog` и `/public-terms`.
В примере canonical/social URL используют `example.com`; замени их своим публичным
адресом перед использованием. Локальная иллюстрация берётся из `www/widgets-icon.svg`.

```java
public final class Catalog implements PublicPage {
    @Override
    public PublicDocument publicDocument(Map<String, String> parameters) {
        return new PublicDocument(
            "Каталог", "Украшения ручной работы",
            "https://shop.example/catalog", "https://shop.example/photo.png",
            List.of(
                PublicDocument.heading(1, "Каталог"),
                PublicDocument.paragraph("Кулон — 2500 ₽"),
                PublicDocument.image("/photo.png", "Кулон из стекла", 600, 400),
                PublicDocument.link("Условия покупки", "/terms")
            ));
    }

    @Override
    public void create(RootWidget root, PageContext context) {
        // Публичный документ добавит библиотека. Не создавай его повторно!
        // Здесь можно добавить обычные формы, кнопки и другие интерактивные виджеты.
    }
}
```

Нужны импорты `com.kniazkov.widgets.base.*`, `RootWidget`, `java.util.List/Map`.
Страницы регистрируются обычным `Application.addPage`. `PublicDocument` неизменяем:
список копируется, текст экранируется, URL проверяются. HTML API для произвольной
разметки отсутствует. Клиент строит элементы через DOM и `textContent`.

Поддерживаемое подмножество: заголовки h1–h6, абзацы, обычные ссылки и изображения
с обязательными положительными размерами. Это отдельное публичное представление,
а не сериализация существующего дерева `Widget`. Таблицы, Markdown, формы,
обработчики, стили виджетов и их модели автоматически в HTML не преобразуются.
Для них остаётся обычный интерактивный `create`. Это новый контракт страницы,
не новый виджет; изменение не требует новой карточки AllWidgets.

## Граница публичности

Обычный `Page` сохраняет прежнее поведение: GET возвращает оболочку, а `create`
вызывается только при создании интерактивной сессии. Нельзя получать HTML посредством
вызова `create` с фиктивным пользователем или «скрывать» закрытые данные CSS.

`PublicPage.publicDocument` получает только неизменяемую карту **недоверенных**
параметров URL. Доступа к `BrowserSession`, пользователю, вкладке и widget ID нет.
Метод должен читать исключительно общедоступные данные, быть безопасным для
повторного вызова и не выполнять бизнес-команд. Наличие интерфейса не делает
секретные данные публичными автоматически: фильтрация товара/черновика и проверка
его публичности — обязанность приложения. Не используй query `user`, `role`,
`authorized` как разрешение. Даже запрос залогиненного пользователя получает
то же публичное представление.

GET не создаёт дерево виджетов и обработчики. Транспортная browser-сессия создаётся
как раньше; из-за её bootstrap credentials HTML остаётся `Cache-Control: no-store`.
Это не CDN-кэш и не экспорт автономного сайта. Неизвестные маршруты не используют
публичный документ главной страницы. Ошибка провайдера не должна подменяться
успешным ответом с закрытым UI.

## Метаданные и навигация

`title` и `description` публикуются сразу и задают начальные значения моделей
RootWidget. `canonical` и social image должны быть абсолютными HTTP(S) URL без
логина/пароля, либо пустыми. Они не выводятся из Host или параметров запроса.
Социальные метаданные: `og:title`, `og:description`, `og:url`, `og:image`.
Пустые значения удаляют соответствующий элемент. Robots, язык и favicon остаются
настройками приложения. Если нужна персональная индексационная политика, используй
обычный `Page` и существующий RootWidget API; публичный контракт не является
системой авторизации.

При SPA-переходах метаданные принадлежат текущей записи истории; Back/Forward
восстанавливает их. На обычной странице canonical и OG предыдущей публичной страницы
удаляются, а title/description возвращаются к настройкам сайта/нового RootWidget.
Изменения title/description через модели RootWidget работают как прежде; OG-поля
остаются снимком публичного документа, а не реактивной моделью.

## Подключение интерактивности

Первоначальный `.widgets-public` находится в `#widgets-initial`. Пока дерево
загружается, содержимое остаётся читаемым, включая сбой/недоступность транспорта.
При готовности полного снимка навигация одной DOM-операцией заменяет контейнер
на интерактивный root. В нём находится тот же публичный документ и добавленные
`create` виджеты. Публичные элементы не имеют серверных event handlers; ссылки
обрабатывает единственный существующий навигационный обработчик. Нет двойного
дерева и двойной регистрации событий.

Это **замена снимка, не hydration** произвольных виджетов. Геометрия публичного
содержимого совпадает благодаря одной структуре, общему CSS и размерам изображений.
Позиция прокрутки при первом подключении сохраняется. Кнопки и формы появляются
после получения интерактивного дерева, ниже документа. Если данные поменялись между
GET и созданием UI, актуальный документ может отличаться — строгого zero-CLS для
изменяющихся данных, пользовательского CSS и динамических контролов нет.
При раннем переходе по ссылке старый fallback удаляется и не появляется поверх
новой страницы. Серверные/клиентские файлы поставляются одной версией; старый JS
не поддерживает добавленное поле `publicDocument` ответа `new instance`.

## Проверка

- `PublicDocumentTest`: реальный HTTP, текст и метаданные без JS, экранирование,
  URL/размеры, неизменяемость, отсутствие создания private UI, публичные данные
  в `new instance`.
- JS: безопасное создание DOM, удаление старых метаданных, ожидание готовности
  дерева и однократная замена fallback; существующие тесты навигации.
- `public-document.spec.js`, Chromium и WebKit: каталог и длинный текст, сравнение
  HTML и bounding box до/после, JavaScript выключен, ссылки, Back, переход на
  непубличную страницу, сбой bootstrap и ровно один вызов по клику.
- Облачный `npm run test:browser` сохраняет initial/interactive PNG в артефакте
  `public-render-comparison-N`; это снимки интеграционного примера, не новые виджеты.
- Полная Java-проверка: `mvn -B -ntp verify`. В PR записываются SHA, версии и реальные
  результаты облачной сборки и тестов.
