## Особенности окружения

- Maven использовал заранее загруженные зависимости из локального кеша в рабочей папке
  и offline-режим. Подпись release-профиля не требовалась, проверки проекта не отключались.
- Основной CDN Playwright отдал неполный архив. Chromium получен с официального
  `storage.googleapis.com/chrome-for-testing-public`, WebKit — с резервного
  `playwright.download.prss.microsoft.com`. Версии соответствуют `package-lock.json`.
- Недостающие системные библиотеки WebKit получены из официальных пакетов Debian trixie;
  SHA-256 проверен по индексу Debian. Они распакованы локально и подключены к окружению
  тестового браузера. Код браузеров, тесты и их утверждения не изменялись.
- Проверка установленных пакетов Playwright через `ldconfig` не видит локальный `libGLESv2`.
  Поэтому только для этого облачного запуска установлен
  `PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1`: предварительная проверка наличия
  системных пакетов пропущена, загрузка библиотек проверена `ldd` и настоящим запуском.
  **Ни один тест не исключён**, штатный конфиг проектов сохранён. Эта настройка не внесена
  в репозиторий/CI; CI устанавливает пакеты обычным `playwright install --with-deps`.
- Ранние неудачные попытки загрузки браузеров и запуска без библиотек не засчитаны.
  После исправления окружения целиком повторён `npm run test:browser`.

## Найденная при E2E и устранённая гонка вкладок

После logout первая вкладка обновляла общую cookie, а соседняя оставалась со старым CSRF
из bootstrap. Ответ становился обычным отказом и соседняя вкладка застывала с `Client Error`.
Теперь несекретный `X-Widgets-Session` различает поколения документа: сменившаяся cookie
приводит к восстановлению документа, а не к использованию старого канала. Сценарий
проходит в обоих браузерах, включая Back/Forward и повтор старого запроса.

Граница гарантий и интеграция с авторизацией приложения описаны в
[CLIENT_CHANNEL_SECURITY.ru.md](CLIENT_CHANNEL_SECURITY.ru.md). Видимых виджетов задача
не добавляет; новые скриншоты компонентов не требуются.
