# Лимиты загрузки и multipart

По умолчанию Widgets передаёт файл чанками по **64 КиБ**, а ограничение одного
файла — **128 МиБ**. В `Options.Builder` можно выбрать любой целый размер
чанка от 1 байта до **1 МиБ включительно**. Размер файла — отдельное
ограничение: он может быть больше или меньше чанка. Последний или
единственный чанк может быть короче, пустой файл передаётся одним пустым
чанком. Конфигурация вне диапазона чанка отклоняется до запуска сервера.

Лимит всего HTTP-запроса и разобранной формы не равен лимиту бинарного
чанка. Для каждого слушателя Widgets выбирает
`max(1 МиБ, chunkSize + 64 КиБ)` для этих двух бюджетов. Резерв относится
к границам multipart, шести небольшим полям формы и заголовкам частей.
Лимит отдельного бинарного вложения остаётся 1 МиБ; прочие лимиты
слушателя (64 части формы, 8 КиБ заголовка части, 32 КиБ заголовков HTTP)
не увеличиваются. Резерв рассчитан на браузерный запрос Widgets, не на
произвольное число заголовков и полей.
Если приложение находится за обратным прокси, его ограничение тела
запроса обязано пропускать полный объём с этим резервом.

Браузер отправляет бинарную часть под коротким фиксированным именем
`chunk.bin`, а имя выбранного файла отдельно в событии выбора. Имя файла
не должно быть пустым, содержать разделители пути или NUL, либо иметь
больше 255 кодовых единиц UTF-16. Лимит относится к имени, а не к
содержимому файла или длине пути на компьютере.

- Файл больше `maxFileSize` отклоняется до передачи чанков, и
  `FileLoader` показывает максимальный размер.
- Чанк больше настроенного `chunkSize`, но допустимый для HTTP-парсера,
  получает `result: false`, `uploadError: "chunkTooLarge"` и `limitBytes`.
- Если HTTP-слушатель или прокси возвращает 413, браузер показывает
  отдельное сообщение об избыточном объёме всего запроса. Это не
  временная ошибка сети. Следующие файлы по-прежнему можно загружать.

Для локальной интеграционной проверки используйте
`com.kniazkov.widgets.e2e.UploadBoundaryServer` с аргументом порта.
Откройте страницу и выберите файл ровно 1 МиБ, затем 1 МиБ + 1 байт и
затем небольшой файл. Первый и последний должны загрузиться, второй
должен получить объяснение ограничения без передачи бинарного чанка.

Если облачный браузер не переносит выбранные локальные файлы из
системного диалога, откройте `/upload-fixture/manual.html` на том же
тестовом сервере. Кнопки передают созданные на странице образцы в
обычный `FileLoader` во фрейме; обработка и HTTP идут обычным путём.
Системный выбор файла отдельно проверяется браузерными E2E-тестами.
