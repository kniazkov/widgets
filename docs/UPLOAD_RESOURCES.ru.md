# Загрузки: ресурсы, срок жизни и повтор запросов

Задача [R05 / #109](https://github.com/kniazkov/widgets/issues/109).

## Контракт

`FileLoader` принимает чанки в отдельный случайно именованный временный файл.
Имя, присланное браузером, используется только как метаданные. Полный массив файла
не сохраняется ни в дескрипторе `UploadingFile`, ни в подтверждении протокола.

`UploadingFile.onLoad` следует зарегистрировать внутри `FileLoader.onSelect`.
Регистрация после завершения или отмены теперь выбрасывает `IllegalStateException`.
Обработчик запускается не более одного раза, вне блокировки реестра, в пуле из четырёх
потоков с ограниченной очередью. Завершение передачи (100%) не означает успех бизнес-обработки.

**Полученный в `onLoad` объект `UploadedFile` действителен только до возврата из callback,
отмены или истечения абсолютного срока загрузки — что наступит раньше.** После этого
библиотека закрывает открытые через него потоки и удаляет временный файл.
Метаданные доступны и позже, чтение содержимого вызывает `IllegalStateException`.
Сохранение ссылки на дескриптор или файл не продлевает срок хранения.

- `openStream()` — чтение без материализации всего файла; поток следует закрывать.
- `copyTo(Path)` — копия в принадлежащий приложению файл; существующий путь перезаписывается.
- `getContent()` — отдельный массив, принадлежащий вызывающему коду; память и срок его
  хранения теперь ответственность приложения.
- Публичный конструктор `UploadedFile(name, type, byte[])` сохраняет исторический срок жизни:
  массив принадлежит вызывающему коду. Новый конструктор с `Path` принимает владение файлом,
  `close()` удаляет его.

Для асинхронной обработки сначала скопируйте содержимое **внутри callback**, затем передайте
копию в свою ограниченную очередь. Пример `LoadImages` копирует данные перед передачей в
существующий пул обработки изображений; `LoadFiles` использует `copyTo`.

```java
loader.onSelect(upload -> upload.onLoad(file -> {
    try {
        final Path saved = Files.createTempFile(applicationDirectory, "received-", ".bin");
        file.copyTo(saved);
        // Приложение обрабатывает saved и само удаляет его после использования.
    } catch (IOException error) {
        throw new UncheckedIOException(error);
    }
}));
```

Не используйте пользовательское имя файла как доверенный путь. Рабочий каталог загрузок
должен быть закрыт от HTTP-раздачи и доступен только процессу приложения.

## Лимиты

`Options.Builder.setUploadLimits(UploadLimits)` задаёт общую политику одного `Application`.
Отдельно созданный `RootWidget` получает собственный реестр; для общих квот передайте ему
один и тот же `UploadRegistry`.

| Ограничение | По умолчанию |
|---|---:|
| Выбранные, принимаемые и обрабатываемые файлы одного клиента | 16 |
| То же для всех клиентов приложения вместе | 64 |
| Сумма заявленных размеров, включая ожидающие и работающие callbacks | 256 MiB |
| Абсолютное время от выбора файла, включая обработку | 300 секунд |
| Лёгкие подтверждения завершения на приложение | 256 |
| Срок подтверждения после последнего принятого чанка | 60 секунд |
| Отдельный файл (`Options.maxFileSize`) | 128 MiB |
| Чанк (`Options.chunkSize`) | 64 KiB |
| Каталог | `java.io.tmpdir` |

```java
final Options options = new Options.Builder()
    .setUploadLimits(new UploadLimits(8, 32, 128L * 1024 * 1024,
        300000, 128, 60000, Path.of("/var/lib/my-app/uploads")))
    .build();
```

Размер резервируется целиком при выборе, до создания файла; нулевой файл тоже занимает
слот. При отказе по квоте `onSelect` не вызывается, бинарный запрос получает `result: false`,
браузер удаляет его из очереди. Автоматического ожидания свободной квоты нет: файл можно
выбрать заново. Счётчики `getActiveCount`, `getReservedBytes`, `getReceiptCount` доступны
через `root.getUploadRegistry()`.

`cancel()` закрывает ресурсы, отменяет ожидающий callback и прерывает выполняющийся.
Прерывание не откатывает уже выполненные действия и не может принудительно остановить
код приложения, игнорирующий interrupt. Такой код занимает один из четырёх потоков;
размер очереди ограничен. Квоты библиотеки не ограничивают копии, созданные приложением.

Удаление клиента, отзыв сессии, удаление загрузчика, неверный чанк, ошибка выбора/обработки
и тайм-аут освобождают ресурсы. Фоновая уборка выполняется раз в секунду даже без запросов.
При ошибке удаления квота сохраняется, уборка повторяется. После аварийного завершения JVM
фоновой уборки нет: очистку старых файлов выделенного каталога при остановленном приложении
обеспечивает эксплуатация (например, политика временного каталога).

## Повторы и совместимость

Формат бинарного протокола не изменён. До завершения поддерживаются перестановка чанков
и повтор с идентичными байтами. После завершения хранится только SHA-256, индекс и длина
завершающего чанка и конечный `nextChunk`. Точный повтор этого запроса получает прежний
успешный ACK, даже когда файл уже удалён; `onLoad` повторно не вызывается. Другой чанк,
изменённые байты, истёкшее или вытесненное подтверждение получают отказ.

Идентификаторы выбора монотонны в пределах загрузчика. Старые метаданные не создают загрузку
повторно после истечения подтверждения. Это не гарантия бизнес-идемпотентности при новом
выборе файла. При disposal браузер очищает очереди, ссылки на `File` и таймеры повтора.

Внешний вид FileLoader не менялся; новых виджетов нет. Существующие AllWidgets и изображения
каталога остаются актуальны.

## Проверки

`UploadResourcesTest`: десять последовательных файлов по 64 KiB, освобождение содержимого,
потоков и диска; ограничение и TTL подтверждений; отмена, неверные чанки, отсоединение,
ошибки callback; потоковое копирование; восемь конкурентных клиентов; четыре работающих
и два ожидающих callback; фоновая очистка без polling со стороны клиента.

`upload-lifecycle.spec.js`: прогресс 50%, отмена, следующий файл; потеря последнего ответа
и успешный повтор после освобождения ресурсов. Выполняется в Chromium и WebKit.
`upload.test.js`: освобождение браузерных ссылок и прекращение повторов после disposal.

Лимиты целого файла, бинарного чанка и полного multipart-запроса описаны
отдельно: [Лимиты загрузки и multipart](UPLOAD_MULTIPART_LIMITS.ru.md).
