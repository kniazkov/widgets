# R40: границы модулей (проект реализации)

Статус: проектирование; перечисленные артефакты ещё не реализованы.
База: b92443f8b080b59fcc42b5a476f790cb312cfd03.

## Проверенные связи

- `db` использует модели и общие типы; обратная зависимость ядра от базы не нужна.
- SQLite и H2 уже имеют scope test, поэтому исключать их из runtime заново не требуется.
- `ImageLoader` требует metadata-extractor и Openize HEIC;
  `ImageProcessor` — imgscalr. ImageIO-провайдеры TwelveMonkeys подключены транзитивно
  всем потребителям, хотя минимальному интерфейсу не нужны.
- `ImageSource`, SVG и генераторы изображений используются моделями и виджетами:
  перенос всего пакета images в необязательный модуль создаст обратную зависимость.
- HTTP связан с ядром не только Server: Options публично принимает SslOptions,
  UploadingFile использует ContentType, Client вызывает ProtocolSecurity.secret().
- ReleaseInfo перечисляет классы только из code source собственного класса.
  После разделения JAR это перестанет учитывать остальные части сборки.

## Целевая структура

| Артефакт | Содержимое | Зависимости Widgets |
| --- | --- | --- |
| widgets-core | Модели, виджеты, жизненный цикл, протокол, браузерные ресурсы, базовые ImageSource | Нет |
| widgets-http | HTTP/WebSocket listener и обработчики запросов | core |
| widgets-db | Хранилища, запросы, persistence/JDBC API | core |
| widgets-images | Декодирование, EXIF, HEIC, масштабирование и ImageIO-провайдеры | core |
| widgets | Совместимый полный набор с примерами | core, http, db, images |

Драйверы JDBC выбирает приложение. Минимальный веб-потребитель подключает core и
http; ему не нужны db, images, HEIC и сторонние ImageIO-провайдеры. Публичные имена
существующих классов по возможности сохраняются. Пакеты Java сами по себе не
означают границы артефактов; дублирования классов между JAR быть не должно.

## Порядок реализации

1. Развязать зависимости ядра от HTTP: генерацию секрета, проверку origin,
   MIME-типы и TLS-конфигурацию. Для публичного SslOptions явно определить
   совместимый переход; не подменять контракт неявной рефлексией.
2. Ввести Maven reactor и отдельные артефакты, сохранив полный widgets.
   Перенастроить тесты, примеры и команды сборки без циклов между модулями.
3. Переработать ReleaseInfo: учитывать все установленные компоненты Widgets,
   не включать случайные зависимости потребителя и не зависеть от порядка JAR.
   Проверить directory, отдельные JAR и assembly приложения.
4. Собрать независимые минимальный и полный consumer; сравнить runtime dependency
   trees и размер зависимостей. Проверить отсутствие image/database-классов и
   провайдеров в минимальном classpath, а не только отсутствие прямых dependency.
5. Проверить публичную страницу, ресурсы и интерактивность минимального приложения,
   AllWidgets полного приложения, полный Java/JS/E2E набор в облаке.
6. Обновить release pipeline, миграцию Foundry19 и документацию по подключению.

Галочка R40 в основном списке поставлена при взятии в работу по принятому процессу.
Она не заменяет результаты приёмки: до выполнения перечисленного задача не завершена.
