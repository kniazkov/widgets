# Tabs, Accordion и Breadcrumbs

Три блочных виджета для составных экранов. Демонстрация находится в AllWidgets,
карточка «Навигация: вкладки и разделы». [Изображения и матрица классов](WIDGET_GALLERY.ru.md).

## Tabs

```java
Tabs tabs = new Tabs();
tabs.setAccessibleName("Карточка изделия");
tabs.addTab("description", "Описание", () -> new Section(new InputField("Черновик")));
tabs.addTab("delivery", "Доставка", () -> new Section(new TextWidget("Условия доставки")));
root.add(tabs);
tabs.getSelectedKeyModel().setData("delivery");
tabs.reorder(List.of("delivery", "description"));
```

Ключ — уникальная непустая строка, не индекс и не подпись. Первая доступная вкладка
выбирается автоматически. `getSelectedKeyModel()` — собственная реактивная модель:
`setData` возвращает `false` для неизвестного, скрытого, выключенного или уже выбранного
ключа. Пустая строка допустима только при отсутствии доступных вкладок.
Подписки на модели удерживаются слабо, как в остальной библиотеке: приложение хранит
сильную ссылку на слушатель или `Binding`. `deriveWithData` создаёт независимую строковую
модель, не второй контроллер того же виджета.

Политика хранения **keep alive**: фабрика вызывается при первом выборе, затем содержимое
остаётся в скрытом контейнере. Введённый текст, локальное состояние и модели сохраняются.
Переключение не вызывает `dispose`; оно скрывает панель, исключая её из доступного дерева,
Tab-последовательности и обработки серверных событий. Скрытие не останавливает фоновые
задачи приложения: их жизненным циклом управляет владелец. Политики автоматического
уничтожения при каждом переключении в этой версии нет.

## Accordion

```java
Accordion questions = new Accordion(false); // Ноль или один открытый раздел.
questions.setAccessibleName("Частые вопросы");
questions.addSection("care", "Уход", () -> new Section(new TextWidget("Хранить отдельно")));
questions.addSection("shipping", "Доставка", () -> new Section(new TextWidget("По согласованию")));
questions.getExpandedKeysModel().setData(Set.of("care"));
root.add(questions);
```

`new Accordion(true)` допускает несколько открытых разделов. Модель возвращает неизменяемый
набор ключей. Запись неизвестного/недоступного ключа или нескольких ключей в single-режиме
отклоняется целиком. Пустой набор закрывает всё. `deriveWithData` возвращает независимый
read-only снимок. Заголовок — настоящий `button` с `aria-expanded` и `aria-controls`,
содержимое — именованный `region`. Содержимое создаётся лениво и сохраняется как у Tabs.

## Изменение структуры и владение

Общие методы Tabs/Accordion:

| Метод | Контракт |
| --- | --- |
| `getKeys()` | Неизменяемый список ключей в порядке отображения. |
| `reorder(keys)` | Полная перестановка без пропусков и повторов; выбор и экземпляры сохраняются. |
| `setItemVisible(key, false)` | Скрывает заголовок и содержимое, исключает ключ из выбора. |
| `setItemEnabled(key, false)` | Оставляет недоступный заголовок, исключает ключ из выбора. |
| `replaceContent(key, factory)` | Уничтожает старое содержимое; открытое создаётся сразу, закрытое — при следующем открытии. |
| `removeItem(key)` | Окончательно уничтожает заголовок и содержимое. Ключ можно добавить заново с новой фабрикой. |
| `dispose()` | Уничтожает всё дерево; повторно использовать виджет нельзя. |

При удалении/скрытии/выключении активной вкладки выбирается **первая доступная в текущем
порядке**. Accordion просто убирает недоступный ключ. При потере сфокусированного заголовка
или закрытии содержащей фокус панели браузер переводит фокус на доступный заголовок;
если их не осталось — на контейнер. При замене содержащего фокус поддерева фокус сначала возвращается к заголовку.
Фокус вне компонента не перехватывается.
Перестановка восстанавливает фокус и в браузерах без `Element.moveBefore`.

Фабрика должна возвращать новый, пригодный к использованию, неприсоединённый `BlockWidget`.
После передачи деревом владеет компонент: не переносите его заголовки и внутренние панели
через унаследованные методы контейнера, используйте методы по ключу. Замена активного
содержимого проверяет новый экземпляр до уничтожения старого. Исключения фабрик не
превращаются в пользовательские сообщения автоматически. Конфигурация выполняется
в потоке страницы, как у остальных виджетов.

## Клавиатура и доступность

| Компонент | Клавиши |
| --- | --- |
| Tabs | Left/Right — следующий/предыдущий доступный заголовок по кругу; Home/End — первый/последний. Это только фокус, без вызова фабрики. Enter/Space — выбор. Tab — выход к содержимому/следующему элементу. |
| Accordion | Up/Down — заголовки по кругу, Home/End — края. Enter/Space — открыть/закрыть. Все доступные заголовки остаются в обычном Tab-порядке. |
| Breadcrumbs | Обычная клавиатура ссылок; Ctrl/Command+клик и средняя кнопка не перехватываются компонентом. |

Tabs использует `tablist`, `tab`, `tabpanel`, `aria-selected`, `aria-controls` и
`aria-labelledby`; у списка одна точка входа Tab. Назовите компонент через
`setAccessibleName`, особенно если на странице несколько списков. Скрытые и выключенные
заголовки пропускаются стрелками. Сочетания с модификаторами не перехватываются.
Длинные подписи переносятся, высота заголовка растёт, выбранная вкладка подчёркнута.

## Breadcrumbs

```java
Breadcrumbs path = new Breadcrumbs("Путь к изделию", List.of(
    new Breadcrumbs.Item("Главная", "/"),
    new Breadcrumbs.Item("Каталог", "/catalog"),
    new Breadcrumbs.Item("Выбранное украшение", "")
));
root.add(path);
```

Последний пункт — текущая страница (`aria-current=page`), обычный текст. Его URL игнорируется.
Предыдущие пункты — реальные `Link` с непустым href и обычной политикой URL библиотеки.
Компонент не устанавливает собственных обработчиков перехода. `setItems` заменяет путь
целиком и освобождает старые ссылки; `List.of()` очищает путь. `getItems` — неизменяемый
снимок. Путь помещён в именованный `nav` со списком. Выбрана политика переноса полного
текста, без многоточия и потери названий; длинные слова также переносятся.

## Совместимость и проверки

Существующие API не меняются. Новый протокольный снимок `set navigation` связывает только
собственные заголовки и панели; клиент проверяет его полностью до изменения DOM.
Обновляйте Java и упакованные JS/CSS вместе. Внутренний `NavigationPanels` — абстрактная
база реализации, не дополнительный самостоятельный виджет.

Java-тесты: стабильные ключи, lazy/retention, ограничения выбора, перестановка, disposal,
замена, ошибки фабрики и пути. JS-тесты: атомарная проверка снимков, клавиатура,
фокус при перестановке/удалении, пауза и очистка обработчиков. E2E Chromium/WebKit:
320/1280 px, клавиатура, touch, Back/Forward, новые вкладки, обновление содержимого,
границы текста и axe. [Протокол проверки R28](R28_VERIFICATION.ru.md).
