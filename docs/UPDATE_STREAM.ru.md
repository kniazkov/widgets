# Версионированный поток обновлений Widgets

Формат обновлений версионируется независимо от HTTP-транспорта. При `new instance`
браузер предлагает `updateVersion=2` и `updateCapability=sequenced-updates`.
Поддерживаемый сервер подтверждает оба поля и выдаёт публичный `updateEpoch`
для этого экземпляра страницы. Старая версия, пропущенная обязательная
возможность или ответ без подтверждённой версии не приводят к незаметному откату
на старую обработку. Обновляйте сервер и JS-ресурсы вместе. Эпоха потока не
заменяет существующие секреты авторизации, идентификатор сервера или вкладки.

## Snapshot, ACK и повтор

- Новый клиент начинает с checkpoint 0. Его первый кадр содержит исходное
  состояние, построенное вызовом страницы на сервере. `updateBase` обозначает
  подтверждённый префикс, `updateThrough` — последний номер кадра,
  `snapshot` истинно, пока сервер не подтвердил ненулевой префикс. Кадр несёт
  ровно последовательности `updateBase + 1` … `updateThrough` в порядке
  отправки. Глобальные RMId остаются идентификаторами для диагностики;
  пропуски между ними допустимы и не имеют отношения к нумерации канала.
- Синхронизация и передача чанков используют один поток и передают
  `X-Widgets-Update-Epoch` и `lastUpdate=#N`. Сервер не принимает другую эпоху
  или точку выше уже опубликованной; старое допустимое подтверждение из
  параллельного запроса не перематывает поток. Неподтверждённый хвост
  хранится с исходными номерами, поэтому потеря ответа и его повтор не требуют
  повторного выполнения DOM-команд. События браузера имеют собственный ACK.
- Обработчик даёт результат `applied`, `noop` или `failure`. Известный
  идемпотентный no-op, например удаление уже перенесённого ребёнка из
  прежнего контейнера, безопасно подтверждается. Невалидный кадр, разрыв,
  перестановка, исключение и неизвестная обязательная команда не
  подтверждаются; после ошибки команды из этого кадра больше не применяются.
- При несовместимости интерфейс явно блокируется, вместо продолжения с
  неполным DOM. Перезагрузка создаёт новый экземпляр страницы и новый
  snapshot; неопределённые действия старого экземпляра не переигрываются.
  Временный сбой сети по-прежнему повторяет запрос той же эпохи.
  Обычный Back/Forward сохраняет checkpoint вместе с живым DOM; если
  экземпляр уже уничтожен, для страницы строится новый snapshot.

## Интеграционная проверка

На локальном сервере E2E откройте `/update-stream`. Кнопка **Increment model**
увеличивает счётчик после исходного snapshot. **Simulate unsupported update**
передаёт после обычного обновления синтетическую неизвестную команду. Видно
**Valid prefix applied** и сообщение о несовместимости; отметка следующего
обновления не появляется. Перезагрузите страницу: новый snapshot показывает
значение 0, а счётчик снова обновляется. Это пример для тестового сервера,
а не функция, доступная в production.
