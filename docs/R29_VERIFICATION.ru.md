## Среда и команды

Облачный Debian 13, Temurin 21.0.13+9, Maven 3.9.9, Node.js 24.22.1,
Playwright 1.62.1. Версии зависимостей и CI-конфигурация не менялись.
Maven использует имеющийся кэш, браузеры запускаются с локальными официальными
Debian-библиотеками. Проверка ldconfig отключена только в облачной среде, поскольку
она не видит этот каталог; Chromium/WebKit и сами тесты выполняются полностью.

```bash
export JAVA_HOME="$PWD/../tools/jdk"
export MAVEN_HOME="$PWD/../tools/apache-maven-3.9.9"
export MAVEN_ARGS=-o
export PLAYWRIGHT_BROWSERS_PATH="$PWD/../tools/browsers"
export LD_LIBRARY_PATH="$PWD/../tools/libs/usr/lib/x86_64-linux-gnu"
export PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1
"$MAVEN_HOME/bin/mvn" -o verify
npm run test:browser
```

- `mvn -o verify`: **636 Java-тестов**, ошибок и пропусков нет, Checkstyle — 0.
- ESLint/Prettier: успешно. Каталог: **65 классов / 86 PNG**.
- JS: **264 passed**, без пропусков.
- `npm run test:browser`: **успешно**, включая все проверки выше и
  **246 E2E passed (11.5m)** в Chromium/WebKit, без пропусков и встроенных повторов.

В первом завершённом полном прогоне было **245 passed / 1 failed**: WebKit-тест
`adaptive-layout.spec.js:54` не увидел переключения порога формы после клика.
Изменений в адаптивную форму не вносилось. После этого весь её WebKit-набор прошёл
три раза подряд (**12/12**) на том же коде. Причина единичного падения не подтверждена;
оно не выдано за успешную приёмку. Итоговый полный прогон указан выше.

## Сценарии

Java: поколения конфигурации, повторный и устаревший выбор, disabled-пункты,
атомарное отклонение неверного списка/события, чужой корень, скрытый/удалённый якорь,
сохранение содержимого и блокировка событий закрытой панели, диапазон задержек,
независимое владение якорем и содержимым.

JS: flip со всех сторон, shift и visualViewport со смещением, уменьшенная клавиатурой
область, атомарные снимки, клавиатура, Escape до обработчика Dialog, отмена hover-таймера,
отсоединение/возвращение и освобождение обработчиков. Regression-проверки: удаление
якоря во время ответа сервера не приводит к ошибке протокола или повторной отправке
close; tooltip восстанавливает описание после подключения якоря позднее в одном batch;
удаление постороннего виджета не ломает доступные связи подсказки; отключение якоря
отменяет незавершённую команду без повторной отправки cleanup.

E2E в Chromium/WebKit: 320/1280 px, стрелки/Home/End/Enter, отключённые пункты,
однократное действие, длинное меню и touch, сохранение введённого текста, рост содержимого,
уменьшение viewport, внешний клик, удаление якоря с фокусом в панели. Реальный контейнер
с overflow и transform проверяет flip у края, пересчёт при внутренней прокрутке и закрытие
при полном уходе якоря. Отдельная серверная страница проверяет скрытие контейнера
с открытым меню и работоспособность после повторного показа. Java regression сначала
упал на старом коде, затем прошёл: только актуальное закрытие разрешено у скрытого
контейнера, открытие/выбор и устаревшее закрытие по-прежнему отклоняются. Tooltip проверяется через accessible description, hover/focus,
отмену задержки и Escape. Вложенное меню закрывается до Dialog. Axe в Menu/Popover —
без нарушений. Это не утверждение о доступности всех старых примеров AllWidgets.

Уменьшение viewport и JS-модель visualViewport проверяют геометрию при экранной клавиатуре.
Физический iOS/Android и системная мобильная клавиатура на облачном desktop не проверялись.

## Ручная облачная проверка и изображения

Собранная галерея открыта в нативном облачном Chromium 156.0.8078.79:
AllWidgets на `http://127.0.0.1:18087/`. Проверены мышь, клавиатурное открытие Menu,
фокус первого пункта, Escape, поле внутри Popover, Tooltip при Tab-фокусе и его
aria-describedby. При прокрутке Popover автоматически перешёл над кнопкой;
DOM подтвердил `data-placement=top`. Клиентского окна ошибки нет.
После снимков добавлена невизуальная обработка закрытия скрытого контейнера и отмены
события при отключении якоря; эти изменения проверяются Java/JS и итоговыми E2E,
визуальная реализация и исходник AllWidgets после снимков не менялись.

Длинное меню открыто в iframe шириной **320 CSS px**, высотой 920 px: подписи переносятся,
список получает внутреннюю прокрутку. Это настоящий интерфейс, не изображение телефона.
Временная HTML-обёртка для iframe удалена и в PR не включена.

Пять PNG вырезаны из реальных снимков без масштабирования и ретуши:

- `anchored-menu`: normal/open, keyboard focus, disabled item.
- `anchored-popover`: интерактивная панель с полем и кнопками.
- `anchored-tooltip`: текст рядом с кнопкой, фокус остаётся на якоре.
- `anchored-popover-flipped`: панель сверху при якоре у нижней границы.
- `anchored-menu-mobile`: длинное меню на 320 px.

В [manifest](images/widgets/manifest.json) записаны база, хеш AllWidgets, размеры исходных
скриншотов, прямоугольники вырезок и SHA-256 PNG. Все изображения подключены в
[галерею](WIDGET_GALLERY.ru.md), API и ограничения — в [контракт](ANCHORED_OVERLAYS.ru.md).
